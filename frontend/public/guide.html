🔴 เรื่อง Provider — ตัดสินใจก่อนสร้าง OA ตัวแรก

การเลือกว่าจะให้ OA อยู่ Provider เดียวกันหรือแยกกัน ขึ้นอยู่กับว่าเว็บไซต์ที่ OA เหล่านั้นให้บริการ ใช้ฐานข้อมูลลูกค้าร่วมกันหรือไม่ ไม่ใช่กฎตายตัว

!
รวมหรือแยก Provider — เลือกให้ตรงกับโครงสร้างเว็บ เปลี่ยนทีหลังหมายถึงการย้าย OA ซึ่งต้องตั้งค่า webhook ใหม่ทั้งหมด

Provider คือกล่องที่ LINE ใช้จัดกลุ่ม OA ของเจ้าของเดียวกัน สิ่งที่ต้องดูคือ เว็บไซต์ปลายทางของแต่ละ OA ใช้ฐานข้อมูลลูกค้าเดียวกันหรือคนละชุด ห้องแชทของแต่ละ OA แยกจากกันเสมอไม่ว่าจะเลือกแบบไหน

รวม Provider — เว็บเดียว ข้อมูลลูกค้าชุดเดียว
[ ลูกค้า ] --ทัก--> [ LINE OA 01 ] --> [ ห้องแชทของ OA 01 ] \ [ ลูกค้า ] --ทัก--> [ LINE OA 02 ] --> [ ห้องแชทของ OA 02 ] >-- [ เว็บไซต์เดียว · ข้อมูลลูกค้าชุดเดียวกัน ] [ ลูกค้า ] --ทัก--> [ LINE OA 03 ] --> [ ห้องแชทของ OA 03 ] /
  • ใช้เมื่อ OA หลายตัวเป็นช่องทางเข้าของเว็บเดียวกัน เช่น แยกตามแคมเปญหรือแยกตามทีมที่ดูแล
  • ห้องแชทยังแยกกันตาม OA ที่ลูกค้าทักเข้ามา แต่ยอดเงินและประวัติที่ดึงมาแสดงเป็นข้อมูลชุดเดียวกัน
  • ลูกค้าคนเดียวทักเข้ามาคนละ OA จะเห็นข้อมูลบัญชีตรงกันทุกทาง
แยก Provider — คนละเว็บ คนละฐานข้อมูล
[ ลูกค้า ] --ทัก--> [ LINE OA (A) ] --> [ เว็บไซต์ A · ข้อมูลของ A ] [ ลูกค้า ] --ทัก--> [ LINE OA (B) ] --> [ เว็บไซต์ B · ข้อมูลของ B ] [ ลูกค้า ] --ทัก--> [ LINE OA (C) ] --> [ เว็บไซต์ C · ข้อมูลของ C ]
  • ใช้เมื่อแต่ละ OA ให้บริการคนละเว็บ ซึ่งมีทะเบียนลูกค้า ยอดเงิน และกติกาของตัวเอง
  • ข้อมูลของแต่ละเว็บไม่ปนกัน ลูกค้าที่สมัครไว้กับเว็บ A จะไม่ถูกมองว่าเป็นลูกค้าของเว็บ B
  • เหมาะกับกรณีที่เจ้าของเว็บเป็นคนละราย หรือต้องการให้สิทธิ์การเข้าถึงแยกขาดจากกัน

ข้อควรระวัง — หากรวม OA ที่เสิร์ฟคนละเว็บไว้ Provider เดียวกัน ข้อมูลลูกค้าจากคนละเว็บจะถูกอ่านเป็นชุดเดียวกัน และแอดมินจะเห็นยอดเงินของอีกเว็บหนึ่งในห้องแชทที่ไม่เกี่ยวข้อง

สร้าง “กลุ่มเครือข่าย” ก่อน

🔴 ต้องทำก่อนเสมอ — ไม่มีกลุ่มเครือข่าย = สร้าง Hook ไม่ได้ ในฟอร์มสร้าง Hook ช่อง กลุ่มเครือข่าย เป็นช่องบังคับ (*) และเป็น dropdown ให้เลือกเท่านั้น พิมพ์เองไม่ได้ ถ้ายังไม่เคยสร้างกลุ่มไว้ dropdown จะว่าง แล้วจะติดที่ “จำเป็นต้องกรอก” บันทึกไม่ผ่าน

กลุ่มเครือข่ายคืออะไร: เป็นตัวจัดกลุ่มว่า Hook ตัวไหนเป็นของลูกค้า/ทีมไหน และใช้คุมว่า ผู้ใช้งานคนไหนเห็นข้อมูลของกลุ่มไหนได้บ้าง — ผู้ใช้งานจะเห็นเฉพาะ Hook ที่อยู่ในกลุ่มเครือข่ายที่ตัวเองถูกกำหนดไว้เท่านั้น

วิธีสร้าง

  1. เมนู หัวข้อ แอป → กลุ่มเครือข่าย
  2. กดปุ่มเพิ่ม → เปิดฟอร์ม สร้างกลุ่มเครือข่าย
  3. กรอกข้อมูลตามตารางด้านล่าง → บันทึก
ช่องกรอกอะไรบังคับ
ชื่อกลุ่มเครือข่ายชื่อกลุ่ม เช่น การตลาด*
คำอธิบายอธิบายว่ากลุ่มนี้ใช้กับอะไร เช่น “LINE OA สำหรับกลุ่มเครือข่าย”—
สถานะต้อง เปิดใช้งาน — ถ้าปิด จะไม่ขึ้นให้เลือกในฟอร์ม Hook—
⚠️ กลุ่มที่ปิดสถานะจะไม่โผล่ใน dropdown ฟอร์ม Hook ดึงเฉพาะกลุ่มที่ เปิดใช้งาน เท่านั้น ถ้าหากลุ่มที่เคยสร้างไม่เจอ ให้กลับมาเช็คสถานะก่อน

สร้างผู้ใช้งาน + คัดลอกผู้ใช้งาน (Clone)

💡 ทำไมต้องทำต่อจากกลุ่มเครือข่าย ฟอร์มสร้างผู้ใช้งานบังคับให้เลือก กลุ่มเครือข่าย อย่างน้อย 1 กลุ่ม — ถ้ายังไม่ได้สร้างกลุ่มในขั้นตอนที่ 1 จะไม่มีอะไรให้เลือก และสร้างผู้ใช้งานไม่ได้

เมนู หัวข้อ แอป → ผู้ใช้งาน → เข้าหน้า จัดการผู้ใช้งาน

💡 กลุ่มเครือข่ายเป็นตัวกำหนดว่าคนนี้เห็นอะไรได้บ้าง ผู้ใช้งานจะเห็นเฉพาะข้อมูลของกลุ่มเครือข่ายที่ถูกกำหนดให้เท่านั้น — ถ้าเลือกกลุ่มผิด คนนั้นจะเห็น Hook ผิดชุด หรือไม่เห็นอะไรเลย
⚠️ แก้ไขผู้ใช้งานที่มีอยู่ = เตะออกจากระบบ เวลากดแก้ไขผู้ใช้งาน ระบบจะเตือนก่อนว่า session ของคนนั้นจะถูกเคลียร์และถูกบังคับออกจากระบบ ต้องล็อกอินใหม่ — ถ้าเขากำลังทำงานอยู่ ควรแจ้งก่อน

คัดลอกผู้ใช้งาน (Clone) — สร้างทีละหลายคน

ใช้เมื่อต้องการสร้างผู้ใช้งานหลายคนที่มี บทบาท กลุ่มเครือข่าย และสิทธิ์เหมือนกัน เช่น เปิดทีมแอดมินใหม่ 5 คนที่ดูแลกลุ่มเดียวกัน — ไม่ต้องมานั่งตั้งสิทธิ์ทีละคน

  1. หาผู้ใช้งาน ต้นทาง ที่มีสิทธิ์ตรงกับที่ต้องการอยู่แล้ว
  2. กดไอคอน คัดลอกผู้ใช้งาน (รูปสองแผ่นซ้อนกัน) ที่ท้ายแถวของคนนั้น
  3. เปิดหน้าต่าง คัดลอกผู้ใช้งานหลายรายการ — ด้านบนจะโชว์ สิทธิ์ที่คัดลอกมา (จากผู้ใช้งานต้นทาง) ให้ตรวจก่อน
  4. กรอก ชื่อผู้ใช้ + รหัสผ่าน ของแต่ละคน (ส่วนนี้ต้องกรอกเอง ไม่ถูกคัดลอกมา)
  5. ต้องการเพิ่มคน → กด เพิ่มแถว · ต้องการลบ → กด ลบแถว
  6. กดปุ่ม สร้าง N รายการ ด้านล่าง
สิ่งที่คัดลอกมาให้อัตโนมัติสิ่งที่ต้องกรอกเองทุกแถว
บทบาท (ระดับสิทธิ์)
กลุ่มเครือข่าย
สิทธิ์ทั้งหมด		ชื่อผู้ใช้
รหัสผ่าน
⚠️ ข้อจำกัดและข้อผิดพลาดที่เจอบ่อย
  • สูงสุด 10 รายการต่อครั้ง — เกินกว่านี้ต้องแบ่งทำหลายรอบ
  • ชื่อผู้ใช้ซ้ำกันเองในรายการ → ขึ้น “ชื่อผู้ใช้งานซ้ำในรายการนี้”
  • ถ้ามีแถวไหนผิด จะขึ้น “กรุณาแก้ไขแถวที่มีข้อผิดพลาดก่อนดำเนินการต่อ” — ต้องแก้ให้ครบก่อนถึงจะกดสร้างได้
✅ สำเร็จแล้วจะขึ้น “สร้างผู้ใช้งาน N รายการ ด้วยสิทธิ์เดียวกับ …” — จากนั้นแจกชื่อผู้ใช้/รหัสผ่านให้แต่ละคนไปล็อกอินได้เลย

เตรียมค่าจากฝั่ง LINE

ค่า 3 อย่างนี้หาได้ที่ LINE Developers Console เท่านั้น (ไม่ใช่ OA Manager) → เลือก Provider ที่ OA ตัวนี้อยู่ → เลือก channel แบบ Messaging API ของ OA ตัวนั้น

🔴 ตรวจให้แน่ใจว่าอยู่ที่ channel ของ OA ตัวที่กำลังตั้งค่า

Provider หนึ่งอาจมี OA หลายตัวอยู่ข้างใน ค่าที่หยิบมาต้องเป็นของ channel ตัวที่ตรงกับ OA ที่กำลังตั้งค่าเท่านั้น หากหยิบผิด channel ระบบจะเชื่อมต่อได้แต่ข้อความจะวิ่งเข้าผิด OA

ค่าที่ต้องเอาอยู่ที่แท็บไหนหน้าตา
Channel IDBasic settings (บนสุด)ตัวเลขล้วน เช่น 2001234567
Channel secretBasic settings (เลื่อนลง)ตัวอักษร+ตัวเลข เช่น a1b2c3…
Channel access tokenMessaging API → กดปุ่ม Issuetoken ยาวมาก (long-lived)
⚠️ Access token ต้องกด Issue ก่อน ถ้ายังไม่เคยออก token จะยังไม่มีค่าให้ copy — กด Issue แล้ว copy เก็บไว้ทันที

Slip Verification (ตรวจสลิปโอนเงิน)

ตั้งค่าบัญชีที่จะใช้ตรวจสลิป ได้ที่ Dashboard ของผู้ให้บริการ Swiftcheck

ลิงก์ Swiftcheckใช้ทำอะไร
เข้าสู่ระบบ (Sign in)ล็อกอินเข้า Swiftcheck
Dashboardตั้งค่าบัญชีตรวจสอบรับเงิน + ดูรายการตรวจสลิป
ศูนย์ช่วยเหลือ (help.swiftcheck.example.com)คู่มือการใช้งานของ Swiftcheck เอง
⚠️ เข้าทาง API LOGIN ด้วย E-mail เท่านั้น ถ้า login ด้วยวิธีอื่นจะไม่เห็นเมนูตั้งค่าบัญชีตรวจสอบ

ขั้นตอนเพิ่มบัญชีตรวจสอบที่ Swiftcheck:

  1. เข้าสู่ระบบ → แดชบอร์ด → แท็บ บัญชี → กดปุ่ม + เพิ่ม ที่หัวข้อ “บัญชีตรวจสอบรับเงิน”
  2. กรอกรายละเอียดบัญชี — เลือกธนาคาร, เลขบัญชี, ประเภท (นิติบุคคล/บุคคลธรรมดา), ชื่อบัญชีไทย+อังกฤษ (ตามสมุดบัญชี ไม่ต้องใส่คำนำหน้า) → กด บันทึก
  3. เพิ่มเสร็จจะเห็นบัญชีอยู่ในรายการ — เอา เลขบัญชี นี้ไปใส่ในช่อง เลขบัญชีที่ต้องการตรวจสอบ ของระบบเรา
📖 ดูคู่มือพร้อมภาพในหน้าจอได้เลย ในแท็บ Slip Verification กดปุ่ม ? ข้างช่อง Slip Verify Key หรือ Match Account จะเปิดคู่มือพร้อมภาพประกอบ (คลิกที่ภาพเพื่อขยายได้)
  • เปิดใช้งาน Slip Verification — สวิตช์เปิด/ปิดฟีเจอร์
  • Slip Verify Key — คีย์จากผู้ให้บริการตรวจสลิป
  • Match Account (ตรวจสอบเลขบัญชี) + เลขบัญชีที่ต้องการตรวจสอบ (Match Account Number) — บังคับให้สลิปต้องโอนเข้าบัญชีนี้เท่านั้น
  • ยอดเงินต่ำสุดที่ยอมรับ (บาท) / ยอดเงินสูงสุดที่ยอมรับ / ระยะเวลาสลิปที่ยอมรับ (นาที) — เงื่อนไขการรับสลิป
  • ข้อความเมื่อตรวจพบว่าเป็นรูปภาพทั่วไป (ไม่ใช่ QR Code) — ตอบกลับเมื่อลูกค้าส่งรูปที่ไม่ใช่สลิป
  • Flex … หลายช่อง — เลือกรูปแบบข้อความตอบกลับแต่ละกรณี (สำเร็จ / ล้มเหลว / ซ้ำ / เกินยอด / หมดอายุ)
  • Callback URL (เมื่อตรวจสอบสลิปเสร็จ) + Callback Token (สิทธิ์การเข้าถึง Callback) — ส่งผลตรวจสลิปไปยังระบบอื่น
  • เหตุการณ์ที่ต้องการให้ Callback — ทั้งหมด / เฉพาะรายการที่สำเร็จเท่านั้น / ไม่มี (ไม่ส่ง Callback)
⚠️ ถ้าใส่ Callback URL ต้องใส่ Callback Token ด้วย ไม่งั้นจะขึ้นเตือน “กรุณากรอก Callback Token เมื่อมีการระบุ Callback URL”

นำ Webhook Endpoint ไป Verify ที่ LINE

นี่คือหัวใจ — ถ้า webhook ไม่ติด บอทจะไม่รับข้อความอะไรเลย (พิมพ์อะไรไปก็เงียบ)

  1. คัดลอก URL: เปิด Hook ที่สร้างไว้ → แท็บ การเชื่อมต่อ Channel → กดปุ่มคัดลอกข้าง Webhook Endpoint
  2. เปิด LINE Developers: developers.line.biz/console → เลือก Provider ที่ OA ตัวนี้อยู่ → เลือก channel เดิม ที่หยิบค่ามาตอนขั้นที่ 3
  3. ไปแท็บ Messaging API → เลื่อนหาหัวข้อ Webhook settings
  4. วาง URL: ช่อง Webhook URL กด Edit → วางลิงก์ที่ copy มา → กด Update
  5. กด Verify: ต้องขึ้น Success (แปลว่า LINE ยิงทดสอบมาแล้วระบบตอบกลับ 200)
  6. เปิดสวิตช์ Use webhook ให้เป็น ON
❌ ถ้า Verify ไม่ขึ้น Success
  • status code other than 200 → วาง URL ผิด/ตกตัวอักษร หรือระบบยังไม่พร้อม — ให้ copy จากปุ่มเท่านั้น อย่าพิมพ์เอง
  • error occurred while connecting / timeout → โดเมน/SSL ยังไม่พร้อม หรือถูก firewall บล็อก — รอ deploy เสร็จแล้วลองใหม่
  • แก้ URL แล้วต้องกด Update ก่อน ค่อยกด Verify
⚠️ Verify ผ่านอย่างเดียวยังไม่พอ ต้องเปิด Use webhook ด้วย ไม่งั้นบอทยังไม่ได้รับ event จริง
